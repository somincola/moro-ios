# 界面与导航契约

本文定义 Moro 当前页面层级、状态所有权和导航边界。它替代旧的页面审计、导航重构进度和 Modal 层级快照。

## 根层结构

```text
App
├── Auth / Registration
└── Main Shell
    ├── Home
    ├── Explore
    ├── Inbox
    └── Me
```

- `RootTabCoordinator` 持有根 Tab、Inbox 分段和外部导航意图的状态。
- `MainShellUIKit` 承载系统 Tab Bar、Home 抽屉/主内容层和 Home FAB。
- `MainTabView` 提供四个根页面内容，不额外复制根导航状态。
- Compose 只作为 Home 的独立 FAB 出现；离开 Home、进入沉浸式媒体或外部深链流程时不得残留。

## Home 内部导航

Home Header 的中央 Menu 在以下内容源之间切换：

- Home / Following
- Local
- Federated
- Lists

各时间线保留自己的 ViewModel、内容、分页游标和滚动位置。切换来源不是新建根 Tab，也不通过横向分页手势隐式改变来源。再次点击 Home Tab 时，优先回到 Home 来源，再执行回顶语义。

## Compose 长文与预览

- 标题栏的编辑选项提供专注编辑、帖子预览和附件排序。专注编辑占满键盘上方可用区域，复用当前原生输入框；收起后恢复普通编辑区，正文与选区由同一份状态保留。
- 预览以只读弹层展示正文、内容提示、媒体和投票；正文作为纯文本转义后交给原生富文本渲染，不把用户输入的 HTML 当作标签执行。关闭预览不提交帖子。
- 附件排序使用原生列表拖动及 VoiceOver 上移/下移操作，顺序直接反映到编辑网格、草稿和发布请求；附件 id、ALT、焦点与上传状态跟随原附件，发布期间禁用排序。

## 话题关注与管理

- 标签页标题右侧展示关注状态；初次读取期间及操作期间禁用按钮，失败显示原状态和重试入口，不影响帖子浏览。
- 首页现有时间线菜单在“列表”旁提供“关注的话题”。管理页使用分组列表，点击条目进入现有标签时间线，侧滑取消关注。
- 取消关注成功后才移除管理行；从标签页返回时刷新关注列表。分页只使用服务器 Link 头提供的关系游标，不使用标签 id 猜测下一页。
- 页面实例按账号隔离，账号切换重建状态。旧实例响应不会写入新账号视图。

## Explore 搜索状态

- 默认展示原有推荐；聚焦搜索框进入输入页，隐藏推荐、结果与范围栏，展示最近搜索和已保存搜索。
- 输入文字只更新草稿。键盘搜索键、明确的搜索行或历史记录才提交查询并收起键盘；输入法候选确认不视为提交。
- 清空保留输入页；仅收起键盘也不退出。取消恢复进入前的查询、范围、内容和滚动位置。
- 结果页切换范围立即查询已提交的关键词，支持单字搜索；加载、空态、错误与重试属于结果页。
- 结果页可保存关键词与范围，或返回推荐。保存管理使用 `Route.savedSearches` 分组页面，重命名使用局部 sheet。
- `SearchInteractionState` 持有输入与页面状态，`SearchViewModel` 持有请求与结果，`SearchLibraryStore` 按当前账号存储最多 20 项最近搜索及主动保存的搜索。

## Route 与 Scene

- `Route` 是功能目的地的唯一枚举，覆盖帖子详情、hashtag、账号 lookup、Profile、媒体、Inbox 会话、列表、设置相关页面等。
- `AppRouter` 把 `Route` 映射到具体页面，并管理 NavigationStack 的 push/replace 行为。
- `MoroSceneDescriptor` 描述页面角色，而不是业务数据。当前角色包括 stream、detail、discovery、hero、grouped、task 和 immersive 等语义。
- `MoroSceneRouting` 为每个 Route 选择画布、Top Bar、滚动和展示方式。

功能页面不得自行维护第二套路由枚举。需要新增目的地时，先判断它属于根 Tab、Route 还是局部 Sheet，再选择唯一所有者。

## 页面层级规则

1. 根 Tab 只承载长期入口和各自返回栈。
2. 内容钻取使用 Route push；同一内容的不同入口应落到同一个目的地语义。
3. 创建、编辑、选择器和确认流程使用局部 sheet/fullScreenCover，不写入根 Tab 状态。
4. 图片和视频预览使用 immersive Scene；沉浸式页面隐藏常规 chrome。
5. 外链按设置进入应用内 Web Preview 或系统浏览器，不伪装为内部 Route。
6. Push、Widget、URL Scheme 和 Share handoff 必须先解析目标账号，再切换根入口和内部目的地。

## 状态所有权

| 状态 | 所有者 |
|---|---|
| 当前账号与会话 | `AppState` / `AccountSessionStore` |
| 根 Tab、Inbox 分段、外部 handoff | `RootTabCoordinator` |
| Route 栈 | `AppRouter` |
| Home 来源与各流滚动状态 | Timeline 模块 |
| 帖子互动回写 | `FeedCoordinator` / `PostInteractionService` |
| 局部编辑或选择流程 | 对应页面的单一 destination 状态 |

不得通过多个 Boolean 同时表示互斥弹层；同一页面应使用单一 destination 枚举，确保一次只展示一个局部流程。

## Surface 与安全区

- 主信息流使用全宽 row 与分隔线；卡片只用于有独立语义的摘要、输入、错误或分组内容。
- stream/detail/discovery 等 Scene 从主题语义色获取画布，不在页面内写死白色或黑色。
- Home 内容可以延伸到系统 Tab Bar 下方，但必须避让系统栏和 FAB 的真实点击区域，不能增加整条空白占位。
- Profile 的沉浸式头图、局部圆形 More 按钮和吸顶 Tab 属于独立长期契约。
- 顶部标题、返回、关闭和局部操作由页面角色决定，避免同一层级同时出现多套 chrome。

## 可访问性与验证

- 所有图标按钮必须提供语义化 `accessibilityLabel`，不能依赖图标文件名。
- 默认字号与 Accessibility XXXL 下，标题、Tab、菜单和局部操作不得依靠裁切维持布局。
- 导航改动至少验证：四根页返回栈、Home 回顶、账号切换、Push 深链、媒体关闭、Sheet 取消和深浅色。
- 结构测试只能确认所有权和几何边界；真实安全区、键盘、手势和局部覆盖仍需模拟器或真机复核。
