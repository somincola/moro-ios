# Moro 动效系统

动效用于解释状态变化和确认操作，不作为独立装饰层。交互状态机和数据结果优先于动画是否播放。

## Token

| 类别 | 当前值 |
|---|---|
| duration | `xs 0.10s`、`sm 0.16s`、`md 0.22s`、`lg 0.28s`、`xl 0.50s`、`xxl 0.60s` |
| translation | `xs 2pt`、`sm 4pt`、`md 8pt`、`lg 12pt` |
| scale | 按压 `0.94`、轻弹 `1.06`、强调弹跳 `1.12` |
| opacity | 列表起始 `0`、Modal 背景 `0.38` |

曲线统一使用 `AnimationTokens.easing` 中的 easeOut、easeInOut 和 soft/medium/firm spring，不在页面内创建含义重复的时长与弹簧参数。

## 使用边界

- 按钮按压：使用现有交互组件或 `.moroTapFeedback()`，但不得用额外 tap gesture 吞掉 Button 的原生行为。
- 喜欢、转发等状态确认：使用 `.moroBounce(trigger:)` 或 `PostActionEffectHost`；失败回滚同样必须清晰可见。
- 内容插入与切换：使用 `.moroSlideFade` 或 `.moroStandard`，避免对长列表中所有 cell 同时播放入场。
- Sheet 和局部浮层：由系统转场优先；只有自绘浮层才使用 `.moroModalTransition`。
- 加载：锁定反馈位置，避免文案或 spinner 导致按钮宽度跳动。

## 交互状态

手势与异步操作至少区分：

```text
idle -> preparing -> ready -> committed/loading -> finished -> reset
                   \-> cancelled -> reset
```

- 未达到阈值必须无副作用取消。
- 达到提交点后立即给出可见反馈；请求完成前禁止重复提交。
- 网络结果决定最终状态，动画结束不能被当作业务成功。
- 页面消失、任务取消或状态被外部刷新时，应终止不再可见的延迟动画。

## Reduce Motion

检测 `accessibilityReduceMotion`。开启后保留颜色、图标、计数和进度等状态反馈，弱化或移除位移、缩放、弹跳和粒子效果；不得因此跳过请求、确认或失败回滚。

## 自定义表情的动效边界

时间轴、贴子详情、个人主页回复、搜索预览等高密度滚动界面统一使用 `emojis[].static_url` 渲染贴子内联表情；列表头像保留 `avatar_static` 底图。Home 时间轴正文作者、搜索账号与帖子作者、通知单人／多人头像及通知参与者列表显式接入同一个受限动画资源池，其他列表和辅助头像保持静态。解析层仍同时保留原始 `url` 与 `static_url`，确保 `content` 中的 shortcode 能准确匹配元数据，但滚动界面只创建普通 `NSTextAttachment`，不创建逐表情播放视图。

发帖表情选择器属于用户主动停留和挑选的有限网格：开启“播放动态表情预览”且未启用 Reduce Motion 时加载原始资源，失败时回退 `static_url`；图片视图使用默认 RunLoop 模式，滚动跟踪期间自然暂停。共享图片渲染器默认继续使用原有加载路径，发帖选择器和资料页头像、封面显式启用受限动画预览管线。自定义表情动画仍限制在选择器，避免原生列表中大量解码与 DisplayLink 影响滑动、耗电和内存。

资料页只有身份区头像与封面播放动画，统一遵守“自动播放 GIF”、系统动画自动播放、Reduce Motion 和低电量模式；视口、前后台和头像查看器切换只改变播放状态，不重新请求原始图片。头像和封面帧缓冲分别限制为 2 MiB、8 MiB，失败时回退静态资源。大图查看器支持动态图片，缩放时保持动画，并在后台或系统禁用动画时暂停。

GIFV 循环交接期间保留播放请求状态和最后已显示的画面，不能因播放器瞬时报告暂停而闪出播放按钮或重新露出封面；普通视频播放结束后仍显示重播入口，加载失败仍显示重试。

## 时间轴媒体播放与回收

- 动态头像、原始 GIF、GIFV 和视频统一使用 60% 可见阈值，并结合当前页面、scene、全屏媒体占用和敏感内容揭示状态。保留的时间轴页面通过独立播放 scope 接收启停状态，不以 hosting controller 是否仍在 window 中作为唯一依据。
- 头像额外等待滚动停稳 150ms；滚动期间暂停已有头像动画。离屏后清空显示视图的图片和播放器，资源池仅短暂保留解码 provider；最多 8 个播放上下文、2 个 warm 条目，warm TTL 2 秒，估算 warm 占用不超过 2MiB。动画逐帧解码到 96／128／160px 档位，不预解码全部帧。详情见[时间轴动态头像低内存方案](时间轴动态头像低内存方案.md)。
- 搜索、通知与时间轴共用上述总预算，不按页面各建一套资源池。搜索的 UIKit 表格通过弱引用可见性探针计算头像自身与滚动裁切区域的交集，只在越过阈值时通知 SwiftUI；搜索输入页、导航和切 tab 时使页面 scope 失效。通知参与者弹层使用独立 scope，显示时暂停后方通知列表，关闭后恢复仍可见头像。
- GIF 自动播放开启且系统策略允许时循环播放；关闭自动播放后，点击时间轴播放按钮只播放一轮，结束后恢复播放按钮。原始 GIF 和 GIFV 遵循同样的手动播放规则；离屏或页面失活撤销本次手动播放请求。
- 全屏查看取得独占播放资格，时间轴归还播放器租约。关闭时先解除 AVKit 的播放器引用，再交还资格；自动模式仅恢复仍可见的媒体，手动模式保留播放入口。原始图片查看器和路由视频查看器同样参与播放资格交接。
- GIFV／视频播放器离屏后最多保留 3 个，2 秒后销毁；后台及内存警告清空已停放播放器。普通视频结束状态在保留行中维持，不因播放器缓存到期而自动重播。
- GIFV 的当前队列 item 失败会显示重试；旧租约的 KVO、结束通知和异步回调不能修改新租约的状态。
- 时间轴和全屏 GIFV 支持保存、分享原始文件；服务器返回 GIFV／MP4 时保存为视频，原始 GIF 保留 GIF 动画字节。文件类型不能通过改扩展名伪装。GIF 全屏播放保持静音，不申请有声视频的音频独占。
