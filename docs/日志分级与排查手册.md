# 日志分级与排查手册

默认运行只输出可操作的 warning/error。高频网络、性能和流式日志必须通过 Launch Argument 临时开启，复现后立即关闭。

## 开关

| Launch Argument | 用途 |
|---|---|
| `-moro.debug.logs` | 通用调试信息 |
| `-moro.perf.logs` | 启动、详情和关键路径性能标记 |
| `-moro.network.logs` | 网络请求摘要 |
| `-moro.network.diagnostics` | 网络诊断上下文 |
| `-moro.network.headers` | 请求/响应头；仅在必要时开启 |
| `-moro.network.body` | 截断的 body |
| `-moro.network.body.full` | 完整 body；仅受控本地环境使用 |
| `-moro.stream.logs` | Streaming 连接与事件 |

`headers`、`body` 和 `body.full` 只扩展网络日志，不应作为默认开关。

## 推荐组合

- 启动或卡顿：`-moro.perf.logs`。
- API 失败：先用 `-moro.network.logs`，信息不足再加 `-moro.network.diagnostics`。
- Streaming 断线/重复：`-moro.stream.logs -moro.network.logs`。
- 无法解释的通用状态：短时使用 `-moro.debug.logs`，并优先补结构化错误而不是永久增加噪音。

## 排查流程

1. 固定版本、账号/实例、设备、系统与网络条件。
2. 只打开能回答当前问题的最小开关并复现。
3. 记录首个异常时间点、请求/事件 ID、状态转换与用户可见结果。
4. 根据调用路径、服务端响应和本地状态确认根因；不要把随后出现的取消日志当成首因。
5. 修复后关闭诊断开关，用默认日志再跑一次，确认无新增噪音或敏感数据。

## 安全规则

- 禁止记录 access token、Authorization、OAuth client secret、PKCE verifier、Cookie 和 Keychain 内容。
- 默认不记录草稿正文、私信正文、完整通知、上传媒体二进制和用户资料响应。
- 分享日志前先去除实例域名、账号、帖子 ID、请求体和可关联标识。
- `body.full` 只能用于本地、受控测试账号，不进入 CI、发布 Scheme 或长期截图。
