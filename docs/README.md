## 维护规则

1. 不新增带日期的“计划、审计、阶段总结、完成记录”作为长期事实；有可复用结论时改写进对应契约。
2. 长期文档只记录 Moro 当前架构、行为边界和可重复的验证方法。
3. 已完成的一次性方案在长期约束被吸收后删除，不建立 `archive/` 目录；需要时从 Git 历史恢复。
4. 当前代码与文档冲突时，先验证生产代码，再在同一改动中修正文档。
5. PR/Release 保存一次性测试结果；长期测试文档只记录可重复的矩阵和验收规则。
