# 个人主页交互与布局契约

本文只记录当前仍需长期保持的 Profile 交互与布局边界，不保留一次性实施步骤。

## 页面结构

- 封面、身份区、资料信息、吸顶 Tab 和帖子内容属于同一个纵向滚动体系。不能通过切换滚动容器或禁用内层滚动完成手势交接。
- 展开时封面覆盖顶部安全区域；折叠进度统一驱动导航背景、标题与图标配色，不能改变 Header 实际高度或 Tab 吸附坐标。
- 网络封面加载中或失败时使用语义色纹理底层；空 URL、无效 URL 和实例默认 `missing.png` 都视为无自定义封面。
- 更多按钮只覆盖自身圆形区域。禁止为了按钮材质新增整条 Toolbar 背景，避免破坏沉浸式封面。

## 滚动与 Tab

- 下拉刷新遵循 `pulling -> armed -> refreshing -> finished`。未达到阈值或按住后收回必须取消；提交后 loading 位置稳定，不随内容跳动。
- Tab 在资料内容下自然进入视口，并在导航 Header 下方吸附。长资料、短内容、安全区和动态字号都必须保持同一套测量关系。
- Tab 只切换 Posts / Replies / Media 内容，不隐式刷新、不回顶、不做延迟滚动恢复。重复点击当前 Tab 不执行操作。
- 各分类独立维护 `notLoaded / loading / loaded / error` 和分页状态；首次进入按需加载，成功空列表也属于 `loaded`，异步结果只能写回请求发起时的分类。
- 滚动位置由用户手势和内容尺寸决定；分类切换不保存快照、不做相对吸附点换算，也不因 Header 测量变化主动修正 offset。

## 身份与资料信息

- 头像、关系操作、昵称、handle 与统计组成连续身份带；简介和自定义字段位于后续语义表面。用户应先识别账号与关系，再阅读详细资料。
- BOT、锁定等属于身份辅助信息，与 handle 共用空间，不能独占一行或伪装成操作按钮。
- 关注和通知按钮共用紧凑 Capsule 规则，但分别维护 loading 状态；并发请求时只能暂时禁用另一控件，不能串用进度状态。
- 简介使用完整富文本；@、hashtag 和 URL 使用 `contentLink` 语义色与下划线，并保持原有解析和路由。
- 同时存在 `fields` 与 `formatted_fields` 时优先展示后者；字段验证标记属于字段名，不能放在 value 前造成归属歧义。
- 加入时间不属于当前 Profile 主要信息层级，模型可保留，但页面默认不展示。

## 改动与验证边界

- Profile 结构拆分只能隔离 Chrome 状态、内容流和操作弹层，不得移动封面、Toolbar、ScrollView 的 ZStack / frame / safe-area 层级。
- 修改按钮、弹层或帖子动作时，必须确认封面仍存在、更多按钮仍为局部圆形覆盖、Tab 吸附点与内容起始位置没有变化。
- 高风险改动至少验证浅色、深色、默认字号和 Accessibility XXXL；使用真实已登录页面，不向生产 Profile 注入 mock 内容。
