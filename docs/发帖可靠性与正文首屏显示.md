# 发帖可靠性与正文首屏显示

更新日期：2026-09-10

## 现象与已确认的问题

- 发帖转圈结束后没有明显反馈：原来的异常处理主要使用全局提示，发帖全屏弹窗内没有持续显示错误。尚未取得用户当时的请求日志，不能确定首次提交具体是超时、响应解析失败还是其他错误。
- 重试可能生成重复帖子：创建帖子请求原来没有 `Idempotency-Key`，且成功后仅解除 `isPublishing`，没有锁定编辑器的已完成状态。服务端已保存、客户端未收到成功响应时，再次提交可能新建第二条帖子。
- 时间轴先出现作者和操作栏，正文稍后出现：包含实例自定义表情时，`MixedTextEmojiView` 原来在所有表情图片请求结束后才设置整段 `attributedText`。慢速或不可用的表情地址会拖延整段正文；系统 emoji 不走这条图片等待路径。

## 调整后的行为

1. 提交前固定正文、附件和发布选项，避免异步操作期间请求内容变化。
2. 按实际创建请求生成防重复标识。同一请求重试复用标识，修改正文或发布选项后生成新标识；失败保存的草稿也保留标识，旧草稿仍可读取。
3. 成功结果只处理一次，成功后保持发布按钮禁用和加载指示，直到编辑器退出。正式入口通过父页面的 `composeContext` / 草稿 binding 直接关闭弹窗；关闭请求先于页面刷新回调和草稿清理，避免关闭动画期间再次发送或重新自动保存已发布内容。
4. 失败时在编辑器底部持续显示原因及草稿保存结果。超时、连接中断或响应无法解析时提示“未能确认帖子是否发布成功”，不把未知结果说成确定未发布；保留手动重试。
5. 自定义表情未加载时立即显示正文、链接和 `:shortcode:`，图片到达后再替换；旧图片请求不能覆盖已经更新的内容。

防重复依赖实例对 Mastodon 创建帖子接口的支持。官方说明相同标识的保留时间为一小时，因此不承诺任意间隔、任意兼容服务端都能永久去重。参见 [Mastodon 创建帖子接口](https://docs.joinmastodon.org/methods/statuses/#create)。

## 发布后停留页面的补充检查

- `ComposeViewModel.publish()` 在主线程隔离环境内等待接口和响应解析，`defer` 才解除 `isPublishing`。单纯响应较慢会延长加载；网络超时或解析异常会结束加载并进入错误分支。没有发现“接口仍在等待，却由计时器提前停止加载”的实现。
- 成功路径原本已调用 `dismiss()`，但加载指示只绑定网络请求状态，调用关闭之前已经复原按钮文字。上一轮增加的成功锁定能阻止重复请求，却没有覆盖这段视觉状态；本次加载指示覆盖发布和关闭两个阶段。
- 帖子详情、个人主页、标签页的发布后刷新在独立 `Task` 内执行，没有等待这些网络请求再关闭弹窗。本次仍将关闭请求提前，并由呈现弹窗的父页面清空对应状态，减少对弹窗环境关闭动作的依赖。
- 调试启动参数 `-moro.debug.logs` 可记录 `[Compose] Publish started`、`Publish succeeded; requesting dismissal` 和 `Published composer disappeared`，配合已有网络响应耗时区分接口延迟与退场问题，不记录新正文内容。
- 这些发现确认了可改进的关闭时序，尚不能证明用户原始现场一定发生了关闭动作丢失。

## 验证

- `Moro-UnitTests`：520 项通过，0 失败。覆盖完成后重复调用、并发提交、服务端保存后丢失响应、草稿恢复重试、发布内容变化、旧草稿兼容及正文先于表情图片显示。
- `ComposePublishingUITests`：7 项最终通过，0 失败。使用真实 `ComposeView`、`MastodonClient`、`PostCard` 和 `RootTabCoordinator` 的 item 弹窗结构，保留系统转场动画。网络由隔离的 URLProtocol 测试服务提供，不向真实账号发布测试帖。覆盖立即响应、普通响应、8 秒慢发帖/回复、8 秒测试退场延迟和 15 秒刷新等待；成功一次点击退出，服务端保存后丢失响应再重试仍只有 1 条帖子。
- `ComposeReplyUITests`：7 项通过，覆盖回复预填、立即编辑、取消后重开和草稿恢复。
- 退场测试直接检查真实 ActivityIndicator 和按钮禁用状态，并等待编辑器实际消失；不能将底层时间轴已有结果当作弹窗已关闭。系统工具栏的状态文案位于外层无障碍容器，内部按钮的 label/value 不能作为加载状态断言。测试中的延迟未加入正式关闭逻辑。
- 已检查测试截图：失败信息和草稿状态在键盘上方可见；发布后的正文和表情占位正常显示。完整结果位于本地 `build/qa/compose-publishing/verification.json`。
- 补充关闭回归的分组运行记录、最终每项结果及截图位于本地 `build/qa/compose-dismissal/verification.json`。
- 本地模拟器验证不等同于用户原始设备及网络现场；若纯文字长帖仍出现相同延迟，需要采集该请求和主线程耗时进一步定位。
