# Moro 产品与功能基线

本文只描述当前产品边界和已经存在的能力，不记录实施时间线、完成日志或未来排期。活动工作由团队内部系统维护，版本历史以 Git tag 和 GitHub Release 为准；代码行为与本文冲突时以生产代码为准并同步修正文档。

## 产品定位

Moro 是面向 iOS 的 Mastodon 客户端，核心目标是提供克制、稳定、阅读优先的联邦社交体验。

- 保持 Mastodon 协议语义，不把本地 UI 偏好伪装成服务器能力。
- 优先保证时间线阅读、发帖、互动、通知和账号切换的完整闭环。
- 使用原生平台行为承载导航、辅助功能、系统分享、Widget 和 Push。
- 对网络失败、权限拒绝、空数据和异步竞态提供可恢复状态。

## 顶层信息架构

底部导航固定为四个根入口：

1. `Home`：关注时间线，以及本站、跨站和列表时间线切换。
2. `Explore`：搜索、趋势标签、趋势帖子和账号发现。
3. `Inbox`：Notifications 与 Messages 两类收件内容。
4. `Me`：当前账号资料、帖子和个人内容入口。

Compose 是 Home 上的独立主操作，不是第五个 Tab。根导航、详情路由和弹层边界见《界面与导航契约》。

## 明确边界

- 新增定时发布当前由 `ComposeFeatureAvailability.scheduledPublishing` 统一关闭。已有 Scheduled 列表、数据模型和取消能力继续保留；Compose 不显示入口，也不会从旧草稿向发布请求泄漏定时参数。
- Widget 不读取访问令牌，也不直接请求 Mastodon API；只读取 App Group 中的轻量快照。
- Share Extension 不复制完整 Compose，而是写入共享 staging，再交由主 App 完成编辑与上传。
- Notification Service Extension 负责 Web Push 密文解密、通知内容改写和进程外 badge 聚合；当前不下载富媒体附件，也不持有 Mastodon access token。
- 多语言目前保持仓内 local Swift Package，不因目录整洁而提前拆成独立仓。
- 历史设计尝试、已完成实施计划和阶段性评分不属于当前产品事实，不保留在活动文档中。
