# 设置、反馈与缓存管理

## 更新检查

- 启动及返回前台时异步检查 App Store 已上架版本。成功结果缓存 24 小时，失败在本次运行中退避 1 小时；“关于 Moro”可手动重试。
- 按 App Store storefront 查询，缺失时回退设备地区。StoreKit 的三位国家代码转换为 Lookup 的两位代码；切换商店时不沿用旧商店的更新结论。
- 只比较营销版本的数字分段，不比较 build number，不提示降级。网络失败、商店无数据与“已是最新”分开显示。
- “关于 Moro”行对未查看的新版本显示红点；查看后记录该版本，更新入口继续保留。
- App Store ID：6776115614。评分入口直接打开 `action=write-review` 链接。

## 反馈

- 设置中提供“反馈与建议”和“为 Moro 评分”。邮件反馈统一放在“反馈与建议”，关于页面不再重复提供邮箱入口。
- Mastodon 入口明确标注公开发帖，打开普通发帖编辑器，预填 `@acacius@m.somincola.org #Moro` 并将光标留在下方正文位置。
- 草稿不附加账号、设备或诊断信息，不自动发布。每次创建独立手动草稿，沿用编辑器的保存、取消、可见性选择流程。
- 主动评分弹窗、满意度预筛选和 X 联系方式暂缓。

## 个人页

- 个人页左上角不新增头像按钮；自己的主页通过更多菜单最底部的“设置”打开设置弹窗，首页头像入口保持原样。
- 他人主页的屏蔽与举报使用系统危险操作角色，图标与文字均为红色；解除屏蔽保持普通操作样式。
- 切换账号页面的滑动移除按钮使用红色底色，保留移除确认。

## 缓存边界

| 显示项 | 清理范围 |
| --- | --- |
| 图片与媒体 | `ImageCache` 下载文件、SDWebImage 下载文件及解码内存缓存 |
| 时间轴内容 | `TimelineCache` 的 `.cache` 内容副本与对应内存 |
| 网络缓存 | `URLCache.shared` 的响应缓存 |

保留 Keychain 登录信息、多账号、偏好设置、草稿及分享附件、书签和阅读记录。尤其保留时间轴 `.meta` 中的 last-seen 标记，不执行退出登录的整库清理流程。

Moro 图片磁盘缓存上限 128 MiB，SDWebImage 上限 256 MiB，图片有效期 7 天。Moro 在写入时限额，SDWebImage 使用库提供的过期清理机制。所有大小以实际文件统计为依据，完成删除后重新统计；下载会在后续浏览中重新产生缓存。

Moro 图片磁盘操作在串行 utility 队列执行，清理轮次令清理前开始的下载失去写回资格。读取轮次只使用短锁，不阻塞等待磁盘扫描。时间轴读写共享 actor，清理内容时先移除待写内容，再保留并落盘阅读元数据。

## 验证

- `AppSupportTests`：数字版本比较、商店代码转换、响应身份校验、缓存与手动重试、红点持久化、跨地区与离线状态、并发检查、反馈草稿隔离。
- `StorageManagementTests`：大小限额、过期、实际磁盘统计、等待清理完成、旧下载写回隔离、保留草稿相邻文件、多账号阅读标记保留。
- `AppSupportUITests`：个人页更多菜单设置入口、更新红点与更新入口、反馈草稿和自动键盘、清理交互，以及中文深色大字号页面。

新增文案覆盖应用现有 9 种语言；不变更历史翻译或 App Store 发布版本。
